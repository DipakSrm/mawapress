# M3 Summary: Admin App and Word-like Editor

**Branch:** `feat/m3-admin`, merged via PR. **Tests:** frontend 276 (Vitest) with lint, typecheck and build passing; backend 476 with `-W error`.
M3 was built directly from 6 short briefs. Every task had a Sonnet implementer, a Sonnet reviewer and fix rounds. The whole branch then had an Opus review and one fix wave.

## What was done
- **App foundation (`frontend/`).**
  - Stack: Next.js 15, React 19, TypeScript, Tailwind v4 and shadcn/ui, with brand colours, Mukta and Noto Sans Devanagari fonts, and light/dark themes.
  - The `(public)` route group is ready for M4.
  - The API client is typed from the backend's OpenAPI and keeps the session alive safely:
    - one shared refresh for simultaneous requests
    - CSRF header on cookie requests
    - If-Match support
    - the access token stays in memory only
    - a network blip doesn't log you out
- **Sign-in and admin shell.**
  - Login with rate-limit feedback, and a session that restores itself.
  - Role-aware sidebar, mobile menu and theme toggle.
  - Dashboard with exact counts: my drafts, in review, scheduled, and published in the last 24 h.
- **Posts list.**
  - Filters for status, category, author, language and search, all kept in the URL, with pagination.
  - Every workflow action, sending If-Match: submit, send back with a note, publish, schedule, unschedule, unpublish, unarchive.
  - Publish and unpublish ask for confirmation, listing which language versions go live.
- **Word-like editor (TipTap).**
  - A ribbon toolbar with:
    - styles and fonts (Nepali and English), sizes
    - bold, italic, underline, strikethrough, colours and highlight
    - alignment, line spacing, lists, links
    - images with captions, tables, YouTube and social embeds
  - Clean paste from Word and Google Docs. Keyboard accessible (roving tabindex).
  - The backend renderer gained tables, privacy-friendly YouTube embeds and embed placeholders under a strict allowlist. Imported .docx files now keep real tables.
- **Writing screen.**
  - Nepali and English tabs, each with its own status.
  - Sidebar: category, tags, featured image, excerpt, breaking toggle and schedule.
  - SEO preview for Google and Facebook, with overrides and a slug editor for published versions. A readability checklist.
  - **Autosave.**
    - Saves every 10 s and on blur or Ctrl/Cmd+S, sending only what changed with If-Match.
    - Shows a clear status.
    - Keeps per-user copies on the device, and never silently drops a newer local copy.
    - Handles "someone else edited this" with Load theirs / Overwrite, merging both versions.
    - Guards against creating duplicate posts.
  - Editors' send-back feedback is shown to the reporter.
  - Revisions with restore, Word import with a progress bar and report, and a leave guard.
- **Library and management screens.**
  - Media library: drag-and-drop uploads with progress, alt texts in both languages, delete protection. Its picker is used for inline images and featured images.
  - Categories (tree), tags, users (with confirmation for risky changes), background jobs (retry and retry all), and a profile page where changing your password keeps you signed in.
- **Backend additions:** published-date filters for the posts list, `GET /api/users/authors` for editors, send-back feedback fields, `created_at` on post summaries, and ASCII-only number checks in the renderer.

## Key decisions
- Data is fetched with TanStack Query. The access token lives in memory, and the session is refreshed through an httpOnly cookie plus a CSRF header.
- The editor only produces content the backend renderer accepts. The renderer is the XSS boundary.
- The Appearance / theme settings screen is M4 work.
- A new translation goes live only when published. Publishing a post publishes all of its existing translations, and the confirm dialog says so.
