# M2b Summary: Platform Services

**Branch:** `feat/m2b-platform`, merged via PR. **Tests:** 450 passing with `-W error`.
M2b was built directly from 8 short task briefs, without a full written plan. Every task had a Sonnet implementer, a Sonnet reviewer and fix rounds where needed. The whole branch then had an Opus review and one fix wave.

## What was done
- **Login and sessions.**
  - Refresh tokens are kept in an httpOnly cookie and change on every use. Reusing an old token logs out that whole login session, with a 10-second grace so two open tabs refreshing at once don't trigger it.
  - Logout, plus CSRF protection on cookie-based requests.
  - Changing a password, changing a role or deactivating an account invalidates existing tokens straight away. Changing your own password keeps you signed in with a fresh session.
- **Rate limits.**
  - Login: per IP + email, per IP, and at most 20 failed attempts per account per hour.
  - Search and view counting are also limited.
  - The client IP is read correctly behind Cloudflare (CF-Connecting-IP, or the last X-Forwarded-For entry).
- **Background worker (arq).**
  - Processes the outbox: tells the Next.js site which pages to rebuild and purges Cloudflare (articles, home, category pages, sitemaps, RSS).
  - Failed jobs retry with backoff for up to 10 attempts, then move to a dead-letter list. Admins can view the job list and retry jobs individually or all at once.
  - Also runs:
    - scheduled publishing
    - image variants
    - view-count flushing
    - SEO refresh after a category or author rename
    - cleanup of old refresh tokens
- **Scheduled publishing.**
  - Schedule, unschedule and publish now.
  - A post that keeps failing to publish backs off and gives up after 10 tries, with the error shown to editors.
  - A post published more than 5 minutes late gets the actual publish time.
  - Archived posts can be unarchived.
- **Media.**
  - Uploads go through the API (10 MB, jpeg/png/webp/gif, phone MPO photos accepted). The real file type is checked and photo metadata (EXIF) is removed.
  - Size limits are enforced before the request body is read.
  - WebP sizes 320/640/1024/1600 and a social-share (OG) image are generated in the background.
  - Featured images appear on article cards, article pages and SEO.
  - Storage works on local disk or Cloudflare R2.
- **.docx import.**
  - A Word file becomes a draft with headings, formatting, lists, links and images.
  - Protected against zip bombs, oversized documents and XML entity attacks.
  - At most 2 imports run at a time, and images from a failed import are cleaned up.
- **SEO feeds.** Sitemap index, monthly sitemaps, categories sitemap, Google News sitemap (last 48 h), and RSS for the whole site and per category. All are cached and refreshed on publish.
- **View stats.** Counts views once per visitor per 30 minutes without storing IP addresses, writes them to the database every 60 s without losing counts, and serves a "trending (24 h)" list with a fallback.
- **M2a carry-overs closed:**
  - the last-admin guard
  - password-change validation
  - send-back now requires If-Match
  - redirect path normalisation
  - a slug-format guard before caching 404s
  - a frozen copy of `plain_text` in the search migration
  - paginated revisions
  - clear error codes for over-long input
- **Docs.** README, a complete `.env.example`, and `docs/api-contract.md` describing the API for the admin app (M3) and the public site (M4).

## Key decisions
- Uploads go through the API rather than presigned URLs, so the server checks every file.
- The rate limiter is built in-house on Redis and allows requests through if Redis is down.
- .docx conversion runs inside the request (time-boxed) on its own small thread pool.
- The outbox claims jobs with a lease and records each result in its own short transaction, so delivery is at-least-once.

## Notes for later milestones
- **M3:** handle `REFRESH_STALE` by retrying once and `REFRESH_REUSED` by sending the user to login. Images inside article bodies aren't tracked when media is deleted, so warn editors.
- **M4:** add rewrites for `/sitemap.xml`, `/sitemaps/*`, `/news-sitemap.xml` and `/rss.xml`. Implement the revalidate webhook (`{tags, paths}` with the `x-revalidate-secret` header). The view-stats and search calls must come from the browser.
- **M5:** block direct access to the server so all traffic goes through Cloudflare. Nginx must set `CF-Connecting-IP` from `$remote_addr`. Use R2 storage in production.
- **Accepted minor items:**
  - colour profiles are dropped and animated WebP is flattened
  - per-IP view counting undercounts readers sharing one mobile carrier IP
  - the same SEO refresh can occasionally run twice
